### Answers

#### 209. What is EIGRP? [D | ML]
* **Definition:** Enhanced Interior Gateway Routing Protocol (EIGRP) is a Cisco-developed Interior Gateway Protocol that combines characteristics of both distance-vector and link-state protocols to provide fast convergence and efficient bandwidth use.
* **Key Note:** Originally Cisco-proprietary, EIGRP was later partially opened as an informational IETF standard, but it still runs almost exclusively on Cisco equipment in practice.

#### 210. Why is EIGRP sometimes called an "advanced distance-vector" or "hybrid" protocol? [D | ML]
* **Distance-Vector Traits:** Like RIP, EIGRP learns routes from directly connected neighbors rather than building a full topological map of the entire network like OSPF does.
* **Link-State-Like Traits:** It also forms neighbor relationships using Hello packets, sends incremental (not periodic) updates, and uses a sophisticated loop-free algorithm (DUAL) for fast convergence — behaviors more typical of link-state protocols.

#### 211. What factors make up the EIGRP composite metric by default? [D | ML]
* **Default Factors:** **Bandwidth** and **Delay** of the path (the slowest bandwidth link along the path and the cumulative delay).
* **Available but Unused by Default:** Reliability, Load, and MTU can be factored in via K-value tuning, but are not used in the default metric calculation.

#### 212. What is DUAL, and what problem does it solve? [D | ML]
* **Definition:** Diffusing Update Algorithm (DUAL) is the algorithm EIGRP uses to guarantee loop-free paths and achieve very fast convergence when a route fails.
* **Problem Solved:** Instead of recalculating the entire topology (like SPF in OSPF) or waiting on slow timers (like RIP), DUAL pre-computes a backup path (the feasible successor) wherever mathematically guaranteed to be loop-free, allowing near-instant failover without needing to query neighbors in many cases.

#### 213. What is a successor and a feasible successor in EIGRP? [D | ML]
* **Successor:** The current best (lowest metric) route to a destination — this is the route installed in the routing table.
* **Feasible Successor:** A backup route that is guaranteed loop-free (its reported distance from the neighbor is lower than the successor's total distance), kept in the topology table ready to be instantly promoted if the successor fails.

#### 214. What is an EIGRP Autonomous System (AS) number, and why must it match between neighbors? [D | ML]
* **Definition:** A numeric identifier configured when enabling EIGRP (`router eigrp <AS-number>`) that logically groups routers into the same EIGRP routing domain.
* **Requirement:** Two routers will not form an EIGRP neighbor relationship unless their AS numbers match — this is a fundamental adjacency requirement, similar to how OSPF requires matching Area IDs.

#### 215. How does EIGRP compare to OSPF at a high level? [D | ML]
| Property | EIGRP | OSPF |
| :--- | :--- | :--- |
| Vendor Support | Cisco (primarily) | Open standard, multi-vendor |
| Algorithm | DUAL | Dijkstra SPF |
| Metric | Bandwidth + Delay (composite) | Cost (based on bandwidth) |
| Convergence | Very fast (pre-computed backups) | Fast, but recalculates SPF on change |
| Scalability Structure | AS-based, less rigid hierarchy | Area-based, strict backbone requirement |

#### 216. Configure EIGRP AS 100 to advertise network 192.168.10.0/24. [S | ML]
```
Router(config)# router eigrp 100
Router(config-router)# network 192.168.10.0 0.0.0.255
Router(config-router)# no auto-summary
```
* **Verification:** `show ip eigrp neighbors` to confirm adjacency, and `show ip route eigrp` to confirm the network is being learned/advertised as expected.

#### 217. Two routers configured for EIGRP are not becoming neighbors. What do you check? [T | ML]
1. **AS Number Mismatch:** Confirm both routers are configured with the identical EIGRP AS number.
2. **K-Value Mismatch:** Verify the metric weighting (K-values) match on both routers — a mismatch here prevents adjacency.
3. **Subnet Mismatch:** Confirm both interfaces are on the same subnet.
4. **Authentication Mismatch:** Check for mismatched authentication configuration, if enabled.
5. **ACLs/Physical Layer:** Rule out an access list blocking EIGRP traffic, or a basic Layer 1/2 connectivity issue.

#### 218. How do you verify EIGRP neighbors and learned routes? [T | EL]
* **Neighbors:** `show ip eigrp neighbors` — lists neighbor IP, interface, and hold time.
* **Routes:** `show ip route eigrp` — displays routes learned via EIGRP, marked with the `D` code (for "Diffusing Update Algorithm").
* **Topology Table:** `show ip eigrp topology` — shows successors and feasible successors for deeper troubleshooting.

#### 219. Explain the difference between EIGRP and OSPF using a simple analogy. [N | EL]
* **Analogy:** "OSPF is like every driver carrying an identical, complete road atlas of the entire region and calculating their own best route from it. EIGRP is more like drivers who only talk to their immediate neighbors about road conditions, but they're smart enough to always keep a pre-approved backup route in their back pocket, so if their usual road closes, they can switch to the backup instantly without needing to ask around first."
